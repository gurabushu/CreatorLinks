# インシデント対応 runbook — EncoreCue

**最終更新：** 2026-08-16
**対象：** 個人情報漏洩・システム障害・不正アクセス・決済トラブル
**責任者：** 沖山敦樹（TobojoLabs）

---

## 0. 判断早見表（30 秒版）

| 症状 | 深刻度 | 初動時間 |
|---|---|---|
| **個人情報漏洩の疑い**（メール流出・DB dump 流出・パスワード hash 流出） | 🔴 CRITICAL | 即時 |
| **不正ログイン成功**（管理者権限奪取・実ユーザーなりすまし） | 🔴 CRITICAL | 即時 |
| **決済で二重送金 / 不正 refund** | 🟠 HIGH | 30 分 |
| **サービス全停止** | 🟠 HIGH | 30 分 |
| **一部機能停止**（Stripe / Pusher / Blob 単発） | 🟡 MED | 数時間 |
| **単一ユーザーからのバグ報告** | 🟢 LOW | 24h |

**🔴 CRITICAL の場合：** 即 §1 に従い、**発覚から 3 日以内に個人情報保護委員会へ速報**（APPI 26 条）。

---

## 1. 初動（発覚〜30 分）

### 1.1 発覚

以下いずれかの経路で検知：
- Sentry からアラート（sentry.io Issue 通知）
- Vercel からデプロイ / ランタイムエラー通知
- サポート窓口（`/admin/support`）にユーザー報告
- 自主監査で発見

### 1.2 深刻度を判定（上記早見表）

### 1.3 影響範囲の一次特定

**個人情報漏洩の場合：**
```sql
-- 影響を受けた可能性のあるユーザーの範囲を SQL で切る
-- 例: 2026-08-16 の特定時刻から特定エンドポイントに触れた全ユーザー
SELECT DISTINCT id, email, name, "createdAt"
FROM users
WHERE ... -- 具体条件
ORDER BY "createdAt" DESC;
```

**不正ログインの場合：**
- Vercel Function Logs で該当時刻の /api/auth/callback/credentials アクセスを確認
- 該当ユーザーの `deletedAt` に印を付けて強制ログアウト
- `AUTH_SECRET` ローテーション判断（する場合は全ユーザーログアウト）

**決済トラブルの場合：**
- Stripe Dashboard で該当 PaymentIntent / Transfer / Refund を確認
- `/admin/payments/[id]` で DB 側の状態も参照
- 二重送金なら Stripe support に refund 依頼

### 1.4 一次対応（血止め）

深刻度 🔴 なら即座に：
- 該当機能を Vercel Firewall で遮断 or 該当ページに `notFound()` を返すデプロイ緊急投入
- 該当ユーザーの session 無効化（`deletedAt` set）
- 侵害された API キー / secret のローテーション

### 1.5 記録

対応の全ステップを時刻付きで記録開始：
```
2026-08-16 14:32 発覚（Sentry alert）
2026-08-16 14:35 深刻度: 🔴 CRITICAL（個人情報漏洩）
2026-08-16 14:38 影響範囲: 直近 24h のログインユーザー 12 名
2026-08-16 14:42 一次対応: 該当エンドポイント無効化デプロイ
...
```

## 2. 調査（30 分〜24h）

### 2.1 原因究明

- Sentry の stack trace + breadcrumb
- Vercel Logs（30 日保持、Pro プラン）
- Neon Postgres 監査ログ（Neon Console → Logs）
- Stripe Dashboard の Event Log

### 2.2 スコープ確定

**必ず答えを出す 3 つの問い：**
1. **何が起きたか** — 事象の技術的説明
2. **いつからいつまでか** — 開始時刻・検知時刻・封じ込め時刻
3. **誰に影響したか** — ユーザー数、内容（メール / パスワード hash / 決済情報 等）

### 2.3 追加損害の防止

- 同種の脆弱性が他エンドポイントに無いか監査
- monitoring 強化（新しい alert ルール）

---

## 3. 通知（24h〜72h）

### 3.1 個人情報保護委員会への速報（APPI 26 条 1 項）

**要件：** 個人データの漏えい・滅失・毀損の発生を知った日から **3〜5 日以内** に速報。

**速報先：**
- 個人情報保護委員会 https://www.ppc.go.jp/personalinfo/legal/ （オンライン報告フォーム）

**含める情報：**
1. 事案の概要
2. 影響を受けた個人データの項目・件数
3. 発生原因
4. 二次被害の有無
5. 本人への通知状況
6. 公表状況
7. 再発防止策の状況
8. その他参考事項

### 3.2 本人通知（APPI 26 条 2 項）

**要件：** 影響を受けた本人に**速やか**に通知（メール / サービス内通知）。

**テンプレート：**
```
件名: 【重要】EncoreCue における個人情報漏えいのお詫びとご報告

〇〇 様

EncoreCue（運営: TobojoLabs 沖山敦樹）をご利用いただきありがとうございます。

このたび、当サービスにおきまして、下記のとおり個人情報が漏えい
した可能性があることが判明いたしました。心よりお詫び申し上げます。

■ 事案の概要
（何が起きたか）

■ 影響を受けた情報
（メールアドレス / 氏名 / 等）

■ 発生日時
（YYYY-MM-DD HH:MM）

■ 二次被害
（有無・具体的内容）

■ 対応状況
（実施済み対応・今後の対応）

■ お客様にお願いしたいこと
（パスワード変更 / 不審メール注意 等）

■ お問い合わせ先
tonokyama@gmail.com

再発防止に努めてまいります。ご不便をおかけし申し訳ございません。

TobojoLabs 沖山敦樹
```

### 3.3 サービス内公表

- `/announcements` に事案の概要を公開
- 必要に応じてトップページのバナー
- Twitter / GitHub Issue で技術詳細を追記（軽微でない場合）

---

## 4. 事後対応（1 週間〜1 ヶ月）

### 4.1 個人情報保護委員会への確報（30 日以内）

速報の 30 日以内（不正アクセスの場合は 60 日以内）に、**確報**を提出。速報時点で判明していなかった詳細を追加。

### 4.2 再発防止策の実装

- 発生原因を潰す修正コミット
- 監査項目に追加
- runbook 自体を更新

### 4.3 教訓の記録

`docs/incidents/YYYY-MM-DD-<slug>.md` として個別 postmortem を残す：
- 事象の詳細
- タイムライン
- 根本原因（Five Whys）
- 実施した対応
- 実施しなかった対応と理由
- 学び
- Action items

```bash
cd apps/web
vercel env rm STRIPE_SECRET_KEY production
vercel env add STRIPE_SECRET_KEY production
# 値を入力
vercel --prod  # 即再デプロイ
```
